# XCL capability matrix for Xbox2Windows

Reference date: 2026-11-23. XCL is pinned at [ivall/xcl@38b05b7](https://github.com/ivall/xcl/commit/38b05b7b6954cfa5bd21cec72f68823603ca2227). The rules for reading XCL are in the [XCL reference](xcl-reference.md); the backlog IDs come from the [XCL reference plan](xcl-reference-plan.md).

Each row is one backlog item. The XCL column records what the pinned project publishes or what an observation at that commit showed. It is never an Xbox2Windows measurement. The Xbox2Windows column describes this tree at the date above. The first action is the smallest next step that reduces the gap; it is not the full implementation.

Status words used in the Xbox2Windows column:

- **Measured**: a committed fixture exercises the behaviour under test.
- **Partial**: part of the area has a committed fixture; the rest is absent or unverified.
- **Tooling**: a script, probe or shim exists, but the runtime path is not measured.
- **Absent**: no implementation was found in the tree.
- **Documented**: a committed note records the state; this is not a runtime measurement.
- **Hypothesis**: an expected gap or expected behaviour that the first action must confirm.

## How to update this matrix

- Keep one row per backlog ID and do not renumber existing items. New work gets a new ID from the orchestrator.
- A row moves to **Measured** only when a committed Xbox2Windows fixture or a linked `docs/experiments.md` section names the command and result. An XCL run never moves a row.
- Record a new XCL observation in the [XCL reference](xcl-reference.md) with the commit, date and environment. Keep this table to the comparison and the next action.
- To move the pin, change the commit and date here and in the reference note in the same change, then re-read every XCL cell that depends on it. Do not carry an old observation under a new commit.
- Mark an expectation that has not been confirmed as **Hypothesis**, and name the observation or fixture that would confirm it.
- Keep title data, shader bytes, generated output and distribution links out of this file. Counts and synthetic fixture descriptions are enough.

The matrix is a snapshot, not a roadmap promise. It should change when evidence lands, and it should stay readable by someone who has not read the XCL project.
